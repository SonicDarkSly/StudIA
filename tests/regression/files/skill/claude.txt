## Utilisation
Cette skill vérifie que le fichier `CHANGELOG.md` respecte les conventions du format [Keep a Changelog](https://keepachangelog.com/). Elle s'active automatiquement lorsque l'utilisateur demande explicitement de "vérifier le changelog" ou "valider le journal des modifications".

## Procédure de vérification
1. Vérifie que le fichier `CHANGELOG.md` existe dans le projet.
2. Lit le contenu du fichier et analyse les sections :
   - La première section doit être **Unreleased** (non datée).
   - Les versions suivantes doivent être datées au format AAAA-MM-JJ.
   - Chaque version doit contenir des sous-sections pour les catégories : Added, Changed, Fixed, Removed, Deprecated, Security.
3. Si des erreurs sont trouvées, elles sont listées avec leur ligne respective.

## Pourquoi cette procédure ?
Le format Keep a Changelog est une convention largement adoptée dans les projets open source pour maintenir un journal des modifications lisible et structuré. Une vérification automatique évite les erreurs humaines avant une release.

## Résultats attendus
Un rapport d'erreurs si le fichier ne respecte pas le format, ou un message confirmant que le fichier est valide.

## Fichiers utilisés
- `CHANGELOG.md` : le fichier à vérifier (dans le projet).
- `scripts/verifier.sh` : script de vérification avec les règles précises.

## À vérifier

#!/bin/bash

set -euo pipefail

# Récupère le chemin du dossier de la skill
SKILL_DIR="$(dirname "$0")"
PROJECT_ROOT="$(dirname "$SKILL_DIR")"

CHANGELOG_FILE="$PROJECT_ROOT/CHANGELOG.md"

if [[ ! -f "$CHANGELOG_FILE" ]]; then
  echo "ERREUR: Le fichier CHANGELOG.md est introuvable dans le projet."
  exit 1
fi

# Vérifie que la première section est "Unreleased"
first_line=$(head -n 1 "$CHANGELOG_FILE")
if [[ ! "$first_line" =~ ^##\ Unreleased$ ]]; then
  echo "ERREUR: La première section doit être '## Unreleased', trouvée : '$first_line'"
  exit 1
fi

# Vérifie les sections de version datées
awk '
BEGIN { in_version = 0; expected_categories = "Added,Changed,Fixed,Removed,Deprecated,Security" }
/^## / {
  if (in_version == 1) {
    # On quitte la section précédente
    print "ERREUR: La section de version n\'a pas de catégories valides."
    exit 1
  }
  in_version = 0
  line = $0
  if (line ~ /^## Unreleased$/) {
    # C\'est OK, c\'est la section non datée
    next
  } else if (line ~ /^## \[.*\] - [0-9]{4}-[0-9]{2}-[0-9]{2}$/) {
    # C\'est une version datée
    in_version = 1
    next
  } else {
    print "ERREUR: Format de version incorrect : " line
    exit 1
  }
}
in_version == 1 && /^### / {
  category = $0
  gsub(/^### /, "", category)
  if (category !~ /^(Added|Changed|Fixed|Removed|Deprecated|Security)$/) {
    print "ERREUR: Catégorie inconnue dans la version : " category
    exit 1
  }
}
' "$CHANGELOG_FILE"

echo "SUCCESS: Le fichier CHANGELOG.md respecte le format Keep a Changelog."

# Règles de vérification du CHANGELOG.md

## Format général
Le fichier doit suivre le format [Keep a Changelog](https://keepachangelog.com/).

## Première section
La première section doit être `## Unreleased`.

## Sections de versions
Les sections de version doivent être au format :
`## [VERSION] - AAAA-MM-JJ`

Exemple : `## [1.2.0] - 2023-05-15`

## Catégories
Chaque version doit contenir les sous-sections suivantes (dans l'ordre) :
1. Added
2. Changed
3. Fixed
4. Removed
5. Deprecated
6. Security

Les catégories doivent être écrites avec une majuscule au début : `### Added`, `### Changed`, etc.

## Exemple de structure valide
```
# Changelog

## [Unreleased]
### Added
- Nouvelle fonctionnalité

### Changed
- Amélioration

## [1.0.0] - 2023-01-01
### Fixed
- Correction d'un bug
```
