1. Vérifie que le projet contient un `package.json` avec un script `start` (ex: `"start": "node src/index.js"`).  
   *Pourquoi* : Le lanceur doit exécuter le même point d’entrée que `npm start`.

2. Crée le fichier `assets/launcher.sh` si absent, avec le contenu suivant :
```bash
#!/bin/bash
# Lanceur pour macOS/Linux (exécutable autonome)
set -e

# Chemin du dossier courant
DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"

# Démarrer l'application via Node.js
exec node "$DIR/src/index.js" "$@"
```
   *Pourquoi* : Ce script est le point d’entrée pour les systèmes Unix. Il garantit que `node` est lancé avec le bon chemin relatif.

3. Crée le fichier `assets/launcher.bat` si absent, avec le contenu suivant :
```bat
@echo off
:: Lanceur pour Windows (exécutable autonome)
setlocal

:: Chemin du dossier courant
cd /d "%~dp0"

:: Démarrer l'application via Node.js
node src/index.js %*
```
   *Pourquoi* : Windows nécessite une syntaxe `.bat` différente pour le chemin et les arguments.

4. Crée le fichier `assets/launcher.applescript` si absent, avec le contenu suivant :
```applescript
-- Lanceur pour macOS (fichier .app)
tell application "Terminal"
    do script "cd '" & POSIX path of (path to me) & "' && node src/index.js"
end tell
```
   *Pourquoi* : Sur macOS, un `.app` peut être créé avec un script AppleScript pour ouvrir une fenêtre de terminal et lancer le projet.

5. Crée le fichier `assets/launcher.json` avec la configuration pour `pkg` :
```json
{
  "targets": [
    "node18-macos-x64",
    "node18-linux-x64",
    "node18-win-x64"
  ],
  "outputPath": "dist/",
  "scripts": [
    "src/index.js"
  ],
  "assets": [
    "assets/launcher.sh",
    "assets/launcher.bat",
    "assets/launcher.applescript"
  ],
  "name": "mon-projet-lanceur"
}
```
   *Pourquoi* : `pkg` nécessite une configuration précise pour packager les fichiers et cibler les OS.

6. Si le projet n’a pas encore `pkg` installé, exécute :
```bash
npm install --save-dev pkg
```

7. Ajoute un script dans `package.json` :
```json
"scripts": {
  "start": "node src/index.js",
  "build:launcher": "pkg assets/launcher.json"
}
```
   *Pourquoi* : Permet de générer les lanceurs via `npm run build:launcher`.

8. Génère les exécutables en lançant :
```bash
npm run build:launcher
```
   *Pourquoi* : Cela crée `dist/mon-projet-lanceur-macos`, `dist/mon-projet-lanceur-linux`, `dist/mon-projet-lanceur-win.exe`.

10. Pour Windows, le fichier `dist/mon-projet-lanceur-win.exe` est déjà un exécutable double-clic.

### Pièges
- ❌ Ne pas installer `pkg` → le build échoue. *Correction* : exécuter `npm install --save-dev pkg`.
- ❌ Oublier de donner les droits d’exécution sur Linux → le fichier ne démarre pas. *Correction* : `chmod +x dist/mon-projet-lanceur-linux`.
- ❌ Utiliser un chemin absolu dans les scripts → ne fonctionne pas en copiant le lanceur ailleurs. *Correction* : utiliser `"$DIR"` ou `%~dp0` pour le chemin relatif.
- ❌ Ne pas inclure `assets/launcher.sh` dans `pkg` → l’exécutable échoue sur Unix. *Correction* : vérifier que `assets/` est listé dans `launcher.json`.

# Skill `add-launcher`

Ajoute un lanceur double-clic autonome pour macOS, Linux et Windows à un projet Node.js.

## Fonctionnalités
- Génère des exécutables via `pkg`
- Supporte les trois systèmes d’exploitation
- Crée un `.app` propre pour macOS
- Ajoute un script de build dans `package.json`

## Utilisation
1. Active la skill en demandant « ajouter un lanceur »
2. Elle génère automatiquement :
   - Scripts de lancement (`assets/launcher.sh`, `.bat`, `.applescript`)
   - Configuration `pkg` (`assets/launcher.json`)
   - Ajoute le script `build:launcher` dans `package.json`
3. Lance `npm run build:launcher` pour produire les exécutables

## Prérequis
- Projet Node.js avec `src/index.js` et `package.json`
- `pkg` installé (`npm install --save-dev pkg`)

## Fichiers produits
- `dist/mon-projet-lanceur-macos`
- `dist/mon-projet-lanceur-linux`
- `dist/mon-projet-lanceur-win.exe`
- `dist/mon-projet-lanceur.app` (macOS)
- `README.md` mis à jour (si nécessaire)

## À vérifier
- Le script principal est `src/index.js` — si non, modifie `assets/launcher.json` pour le changer.
- Tu dois avoir `pkg` installé en dev : si non, exécute `npm install --save-dev pkg`.
- Sur macOS, l’application peut être bloquée par sécurité. Si c’est le cas, ouvre `System Settings > Privacy & Security`, puis autorise l’exécutable.
- Le projet ne doit pas contenir de dépendances natives non compatibles (ex: `node-gyp`), car elles ne seront pas packagées.
